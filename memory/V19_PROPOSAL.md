# v19 Reconfig Proposal — fixing the self-play plateau

Drafted 2026-06-16, while v18 (`reports/ml/alphazero_v18_absolute`) runs iters 7–10.

## The problem v18 exposed

v18 plateaued: eval `mean_score` stuck in the low 40s (42→47→43→49→40→41 over iters 1–6),
zero promotions, gate win-rate oscillating (0.20/0.15/0.125/0.175/0.225/0.025) with no trend.

**Root cause (code-confirmed):** the self-play champion `best_model.npz` only updates on
promotion (`auto_improve_alphazero.py:1142–1143`), but v18 used `--gate-mode heuristic`, where
promotion requires the candidate to beat the **rule-based heuristic** at ≥50%
(`:1099–1107`, threshold check `:1120`). The heuristic averages ~67–69 pts; the cold-start NN
averages ~40–50. So the NN never clears the gate → `best_model.npz` stays frozen at the boot
model → every iteration's self-play data is generated by the same weak champion
(`:599–600`) → the model can't bootstrap. Training warm-starts candidate-to-candidate
(`:958–963`), but the *data source* never improves, which caps everything.

There is **no flag** to make self-play use the latest candidate instead of the frozen champion;
the only lever that advances the champion is making promotions actually happen.

## The fix: `--gate-mode champion` (no code change needed)

`gate_mode` accepts exactly two values: `"heuristic"` and `"champion"` (`:1385–1390`).
The `champion` branch (`:1064–1098`) plays the **candidate NN vs the previous champion NN**,
both running MCTS at `--gate-mcts-sims` — an apples-to-apples comparison. Two-stage:
20 games, and if candidate ≥0.5, another 20 (`:1066–1093`). Promotion still uses the same
threshold check at `:1120`.

**Why this ratchets upward:** the promotion question becomes "is the new model better than the
*last* model" instead of "is it better than a strong hand-written bot." A cold-start model only
has to beat its own predecessor — no absolute-skill floor. Each promotion overwrites
`best_model.npz` (`:1143`), so the next iteration's self-play data comes from a stronger champion.
Champion strength becomes monotone non-decreasing — the standard AlphaZero ratchet.

First-iter: with champion seeding on (default, `:538–540`), iter 1 candidate plays the seed
model. Either way iter 1 establishes a champion (auto-promote fallback at `:1124`).

## Known caveats (decide before launch)

1. **Noisy gate.** At `--gate-mcts-sims 40` over 20–40 games, a true coin-flip candidate has
   ~50% chance of spuriously promoting. The Wilson CI95 *is* computed (`:1115–1119`) but **not
   enforced** in the promotion decision — only the point estimate `win_rate >= threshold`
   (`:1120`) gates. Mitigations: raise `--gate-stage-games` and/or `--gate-mcts-sims`, set
   `--min-promotion-win-rate` slightly above 0.5, or (small code change) enforce the CI95 lower
   bound > 0.5.
2. **Regression risk.** Because promotion is point-estimate, a lucky-but-worse candidate can
   replace a good champion. Higher games + threshold mitigate.

## Recommended v19 config

```bash
nohup env PYTHONPATH=. python -m backend.ml.auto_improve_alphazero \
  --out-dir reports/ml/alphazero_v19_champion \
  --train-init-model-path reports/ml/_boot/boot_model.npz \
  --value-target-mode absolute --use-modal \
  --gate-mode champion \
  --min-promotion-win-rate 0.55 \
  --gate-mcts-sims 60 \
  --gate-stage-games 30 \
  --iterations 15 --games-per-iter 200 --mcts-sims 100 \
  --train-epochs 10 --eval-games 40 --promotion-games 40 --dataset-workers 32 \
  --pilot-early-stop-iter 999 \
  --use-per-slot-encoding --enable-identity-features \
  --use-hand-habitat-features --use-power-features \
  > reports/ml/alphazero_v19_champion_run.log 2>&1 &
```

Rationale for the changed knobs vs v18:
- `--gate-mode champion` — the core fix.
- `--min-promotion-win-rate 0.55` — classic AlphaZero bar; reduces spurious promotions.
- `--gate-mcts-sims 60` + `--gate-stage-games 30` — cut gate noise (vs defaults 40/20);
  up to 60 games/iter in the gate. Costs more compute per iter.
- `--iterations 15` — give the ratchet room to compound now that it can.
- Everything else (encoder flags, absolute target, 200 games, 100 sims, 10 epochs) unchanged
  from v18 so results are comparable.

## Optional code hardening (not required to launch)

Enforce the already-computed CI95 lower bound in the promotion decision (`:1120`): require
`ci95_low >= min_promotion_win_rate` instead of the point estimate. ~3-line change; makes
promotions statistically honest at the cost of slower ratcheting. Recommend only if we see
regressions in a first champion-mode run.

## Decision points for the user
- Launch v19 after v18 finishes, or sooner in parallel? (Modal has capacity for both.)
- Accept the recommended threshold/gate-noise settings, or go stricter/looser?
- Want the CI95-enforcement code change before launch, or run with point-estimate first?
