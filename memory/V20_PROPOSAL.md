# v20 Proposal — make the champion ratchet compound

## Goal
v19 proved champion-gate works (1 promotion, strong model) but stalled in a **single-promotion
regime**: candidates cluster at ~0.40 gate WR vs the iter-1 champion and never clear 0.55. v20's
goal is **repeated promotions** so the champion compounds across iterations.

## Corrected diagnosis (verified against the v19 code + log)
The earlier guess ("no replay buffer / low data diversity") was **wrong**. The replay buffer is on
by default (`--data-accumulation-enabled`, `--data-accumulation-decay 0.5`,
`--max-accumulated-samples 200000`) and v19 used it — the log shows the combined dataset growing
`31200 → 72800` samples across iters with `decay=0.500`. The real cause of the plateau:

- **Every candidate warm-starts from the champion** (`warm-start from best_model.npz | applied=32`)
  **and** trains on a replay buffer that is **dominated by that same champion's self-play** (decay
  0.5 → recent iters, all generated by the iter-1 champion, dominate; the only non-champion data is
  iter-1's weak boot games, which decay to ~3% weight).
- Net effect: each candidate is **fine-tuning the champion on the champion's own games** — anchored
  in the champion's basin, so it reproduces the champion and lands slightly *below* it from training
  noise → gate WR ~0.40, just under the 0.55 bar.

To escape, the candidate needs a learning signal that is genuinely *better* than the champion's
current policy (so there's something to climb toward), plus a bar low enough that real-but-marginal
gains get locked in and compound.

## Proposed changes (priority order)
1. **Lower the promotion bar to 0.50** (`--min-promotion-win-rate 0.50`). Standard AlphaZero. Lets
   genuine marginal improvements promote and compound. Zero extra compute. Highest expected impact.
2. **Stronger self-play targets: `--mcts-sims 100 → 200`.** This is the core AlphaZero improvement
   engine — MCTS search produces a policy stronger than the raw net, giving the candidate a real
   gradient to climb above the champion. Costs ~2× self-play time (Modal-sharded, still ~40–60
   min/iter). Most important *learning* lever.
3. **Loosen the champion anchor.** Two cheap experiments:
   - **`--data-accumulation-decay 0.7`** (or higher) so the buffer keeps more cross-iter variety
     rather than collapsing onto the latest champion, *or*
   - reduce reliance on warm-start (e.g. higher LR / fewer frozen layers) so candidates aren't
     pinned to the champion's basin. (Warm-start helps stability — change one knob at a time.)
4. **More training signal (secondary):** `--train-epochs 10 → 15`, `--games-per-iter 200 → 300`.

## Operational changes (make long runs survivable)
The gate is the wall-clock bottleneck and what makes container reclaims costly. With the bar at
0.50:
- `--gate-mcts-sims 60 → 40`, keep `--gate-stage-games 30` (early-stop on clear decisions).
- Target ≤60 min/iter so more iters fit per container window.
- Expect to resume ~2–4× via `--no-clean --start-iter N` (proven workflow; datasets + best_model
  persist on disk across reclaims).

## Suggested launch (no code change required)
```bash
nohup env PYTHONPATH=. python -m backend.ml.auto_improve_alphazero \
  --out-dir reports/ml/alphazero_v20_compound \
  --train-init-model-path reports/ml/_boot/boot_model.npz \
  --value-target-mode absolute --use-modal \
  --gate-mode champion \
  --min-promotion-win-rate 0.50 \
  --gate-mcts-sims 40 --gate-stage-games 30 \
  --iterations 10 --games-per-iter 300 --mcts-sims 200 \
  --data-accumulation-decay 0.7 \
  --train-epochs 15 --eval-games 40 --promotion-games 40 --dataset-workers 32 \
  --pilot-early-stop-iter 999 \
  --use-per-slot-encoding --enable-identity-features \
  --use-hand-habitat-features --use-power-features \
  > reports/ml/alphazero_v20_compound_run.log 2>&1 &
```
Optionally seed the champion from v19's promoted model instead of boot:
`--train-init-model-path models/champions/v19_iter1_champion.npz` (gives v20 a strong starting
champion and a meaningful first gate). Trade-off: less comparable to v19's boot-seeded start.

## Success criterion
**≥3 promotions**, with self-play mean and eval-vs-heuristic trending up past v19's plateau
(self-play >66, eval >57). If still single-promotion after lowering the bar + stronger targets +
looser anchor, the limiter is model capacity/representation, not the loop — revisit the encoder.

## Preserved artifact
v19's promoted iter-1 champion is saved at `models/champions/v19_iter1_champion.npz`
(+ `.meta.json`) — usable as a v20 seed or as a fixed baseline opponent.
